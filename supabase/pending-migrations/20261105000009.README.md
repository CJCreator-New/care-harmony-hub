# 20261105000009: database integrity, retention and storage

Roadmap S2-08, issues DB-12, DB-20, DB-17, SECF-24. The migration
`20261105000009_db_integrity_hygiene.sql` removes the PHI hard-delete paths,
replaces the destructive cascades, fixes the visit uniqueness constraint, adds
CHECK constraints (NOT VALID) and indexes, adds a retention helper that deletes
nothing unless called, and scopes the `documents` and `telemedicine-recordings`
storage buckets to the hospital. Nothing has been applied to any database.

Read `20261105000008.README.md` first. Several items here depend on it.

## What the migration does

| Section | Issue | Effect |
|---|---|---|
| A | DB-12 | Adds a nullable `deleted_at` to `patients`, `appointments` and `consultations`. A BEFORE DELETE trigger, `trg_<table>_no_hard_delete`, raises for a hard DELETE on those three tables. The trigger also fires on FK cascades. |
| B | DB-12 | Every foreign key whose parent is `patients`, `appointments` or `consultations` and which is `ON DELETE CASCADE` is recreated as `ON DELETE RESTRICT`. `NOT VALID` and `DEFERRABLE` are kept if they were set. |
| C | DB-12 | Drops `unique_active_consultation (patient_id, doctor_id, status)`, which blocked a second completed visit between the same patient and doctor. Adds `consultations_one_open_per_patient_doctor`, a partial unique index on `(patient_id, doctor_id) WHERE status IS DISTINCT FROM 'completed'`. If open duplicates exist, nothing changes and a WARNING is raised. |
| D | DB-12 | Adds CHECKs, all NOT VALID: `appointments_duration_positive`, `appointments_end_after_start`, `patients_dob_not_future`, `patient_queue_service_order`. Each is added only when its columns have the expected type. |
| E | DB-20 | `CREATE INDEX IF NOT EXISTS` on `hospital_id`, `patient_id`, `status` and `created_at` where those columns exist and no index leads with them, on `patients`, `appointments`, `consultations`, `patient_queue`, `lab_orders`, `prescriptions`, `invoices`, `documents` and `telemedicine_sessions`. Also one index for each single-column FK whose parent is `hospitals`, `patients`, `appointments` or `consultations`. |
| F | DB-12 | Creates `public.purge_operational_logs_before(p_table, p_cutoff, p_dry_run default true)`. See "Retention helper". |
| G | DB-17 | Drops the seven `storage.objects` policies on the `documents` bucket (from 20260204000011) and creates three: staff SELECT and INSERT scoped to the folder `<hospital_id>/`, admin-only DELETE. There is no UPDATE policy, so overwrite is refused. |
| H | SECF-24 | Creates the `telemedicine-recordings` bucket as private (or makes an existing one private), limited to `video/webm`. Policies: doctor, nurse and admin SELECT and INSERT scoped to `<hospital_id>/`, admin-only DELETE, no UPDATE. |

Helper functions added: `public.phi_reject_hard_delete()`,
`public.storage_staff_hospital_ids(text[])` (SECURITY DEFINER, STABLE, returns
the hospitals where the caller is active staff with one of the listed roles)
and `public.purge_operational_logs_before(text, timestamptz, boolean)`. All use
`SET search_path = ''`, and EXECUTE on the helpers is limited to what is needed.

## Behaviour changes to expect

- **Hard delete of a patient, appointment or consultation fails.** The message
  says to set `deleted_at`. This is intended (DoD: no PHI hard-delete paths). It
  also means that deleting a hospital with patients fails, because the cascade
  from `hospitals` to `patients` fires the trigger. That cascade was not changed.
  Tenant offboarding needs a separate, reviewed procedure.
- **Deleting a patient that has child rows fails** (RESTRICT instead of cascade).
  The children are appointments, consultations, queue entries and similar rows.
- **`deleted_at` is not filtered by any read.** Client queries still return soft
  deleted rows until the app filters `deleted_at IS NULL`. That is a `src/`
  change.
- **Documents deletes are admin-only.** `src/hooks/useDocuments.ts` (around line
  107) and `src/hooks/useDocumentUpload.ts` (around line 125) delete rows or
  objects. A non-admin delete will be refused.
- **Documents overwrite is refused.** No UPDATE policy means `upsert` on an
  existing object fails. Uploads through `useDocumentUpload` use a new UUID per
  file, so they are not affected.
- **Only the listed roles reach `documents`.** `patient` is not in the role list.
  Check whether any patient-facing path uploads to `documents` (the portal
  documents pages). If one does, it needs its own policy.

## Client changes required before promotion

1. **Telemedicine recordings (SECF-24).** `src/components/telemedicine/VideoCallModal.tsx`
   (around lines 137 to 141) writes to `telemedicine/${sessionId}/recording-…webm`
   with `upsert: true`. The policy requires the first path segment to be the
   hospital id. The upload must become `${hospitalId}/telemedicine/${sessionId}/…`
   and must drop `upsert: true`. The recording path stored in
   `telemedicine_sessions.recording_url` and the playback code (around line 222)
   must use the same path. Without the change, recording uploads fail with
   42501 after promotion.
2. **Deletes on `documents`.** Confirm the admin-only delete is the intended
   behaviour, or add a policy for the owning uploader.
3. **Soft delete reads.** Filter `deleted_at IS NULL` wherever patients,
   appointments or consultations are listed. Without this, "deleted" rows still
   show.

## Retention helper (not scheduled)

```sql
-- Count only (the default):
select public.purge_operational_logs_before('error_logs', now() - interval '365 days');
-- Delete, after reviewing the count:
select public.purge_operational_logs_before('error_logs', now() - interval '365 days', false);
```

- It runs on no schedule. Nothing calls it.
- An explicit cutoff is required. A NULL cutoff raises.
- A cutoff newer than 90 days raises.
- The table must be on the allow-list: `error_logs` and `performance_logs`, both
  by `created_at`. Audit tables and PHI tables are not on it. The audit triggers
  from 20261105000008 would refuse their deletes anyway.
- `p_dry_run` defaults to true, so a call with only a cutoff counts and deletes
  nothing. The stricter default is deliberate.
- EXECUTE is granted to `service_role` only. An operator must confirm that
  `error_logs.context` and `performance_logs` contain no PHI before the first
  delete, because the table is operational.

## Operator steps

1. **Index builds lock writes.** `CREATE INDEX IF NOT EXISTS` without
   CONCURRENTLY takes a write lock on each table while it builds. Run the file in
   a maintenance window on large tables, or build those indexes first with
   `CREATE INDEX CONCURRENTLY` outside a transaction. `IF NOT EXISTS` then skips them.
2. **Duplicate open consultations.** If the WARNING "open duplicate
   consultations exist" appears, the partial index and the removal of
   `unique_active_consultation` are both skipped. Resolve the duplicates by hand,
   with an audited change, and re-run the file. Do not delete clinical rows in
   a migration.
3. **CHECK constraints.** They are NOT VALID, so they check new and updated rows
   only. After the data is cleaned, run
   `ALTER TABLE ... VALIDATE CONSTRAINT <name>` for each. That is a separate,
   reviewed step.
4. **Storage bucket.** The `telemedicine-recordings` bucket is set to private. If
   it already existed as public, the change takes effect immediately.
5. **Re-run check.** Run the file twice on the baseline. It must exit 0 both times.

## Not fixed here

- **DB-20, RLS performance.** Wrapping `auth.uid()` as `(select auth.uid())` in
  about 521 policies, marking the helpers STABLE, and consolidating stacked
  permissive policies are a separate change. Rewriting them in a migration would
  touch every policy. This file adds only the indexes part of DB-20. It does not
  mark helpers STABLE either, because the helpers' bodies were not reviewed here.
- **DB-12, remaining items.** Only four CHECKs are added. The other missing
  CHECKs need a review of each column's domain. The hospital-to-patient cascade
  is unchanged (see "Behaviour changes").
- **SECF-24 path.** The client path change is in "Client changes required".
  The migration cannot make the existing files at `telemedicine/…` comply.
- **Patient-portal documents.** Not checked (see "Behaviour changes").
